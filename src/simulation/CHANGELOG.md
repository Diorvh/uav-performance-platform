# 审查、修复与数据库适配记录

日期：2026-09-05。范围：`悬停续航仿真` 项目源码、已有说明和自动检查；追加适配同级力效数据库。原 Excel、SQLite、实验采用标记及数据库项目源码均未修改。

## 1. 已修复的错误与不严谨之处

| 问题 | 修改与检查 |
|---|---|
| 最大时间 2.5 s、步长 1 s 时，旧汇总为 3 s，最后一行却停在 2 s | 截短末步，时序包含终点；汇总、CSV 末行一致 |
| 容量用完时可能把参考电压当作最终端电压 | 终点重新联立计算带载电压、电流和推进功率 |
| 插值后力效不等于推力/功率 | 只插值功率与转速，力效统一派生；检查功率输入一致性 |
| 电压固定点迭代未保证收敛，且强行夹正电压 | 根据分段线性功率直接解二次方程，检查区间和残差；无解明确失败 |
| 平均值按样本平均；部分初始容量口径不清 | 按时间和本次消耗计算平均 I/P，补 Wh；说明窗口累计 Ah 与本次用量区别 |
| 整步跨过截止条件或曲线拐点 | 按参考曲线及推进层节点分步，并定位截止事件；增加谷值/峰值漏检回归用例 |
| 命中上电压层时仍要求无关下层覆盖目标推力 | 命中单层时只检查该层；跨层插值才要求共同支持 |
| NaN、无穷大、小数旋翼数、负电流限制等可能进入模型 | 模型边界统一校验；增加 200000 步上限、正值/单调性检查 |
| CSV 单位由整张表的关键词猜测，坏行被跳过 | 精确识别每列单位，检查行号、列数、必需值和歧义；拒绝静默丢弃 |
| 功率/力效冲突被覆盖；电输入和轴功率混淆 | 同时提供时检查 3% 舍入差；轴功率单独换算，电输入禁止重复扣损耗 |
| 新参数配旧曲线/旧结果，运行失败仍可导出上次结果 | 输入变化立即清空结果；测试元信息变化要求重导入；失败不保留旧结果 |
| 同步计算卡界面，长表单/五幅小图被窗口截断 | 后台任务、停止按钮、分组参数页、切换曲线，1000×700 等尺寸检查 |
| 反复创建/关闭窗口后，Tk 资源可能在工作线程回收 | 显式指定变量所属窗口、移除变量追踪、主线程释放资源，退出前取消并等待任务结束 |
| 结果写入可能截断旧文件或覆盖原始输入 | 同目录临时写入后原子替换，保护输入路径/硬链接；失败保留旧文件 |
| 把窗口 SOC、数据边界或 k>1 解释成更完整的物理模型 | 界面和 README 明确经验基线、SOC 窗口、停止类别和准稳态适用范围 |

审查遵循“先复现、查根因、局部修复、增加回归检查”的调试流程。没有通过平滑、自动剔除异常点、自动采用实验或未经验证的拟合来掩盖输入问题。

## 2. 新增数据库读取适配

- 新增 `database_adapter.py`：SQLite 独立只读短事务、按字段名读取、逻辑快照哈希、人工采用状态检查、硬件一致性与原始字段校验。
- 新增 `database_dialog.py`：配置筛选、多电压组选择、来源/采用状态/推力范围展示；不提供数据库写按钮。
- 耗电依据改为实测 `V×I`，不采用数据库中扣空载电流后的 `power_w`，也不将其认作轴功率。
- 从 `thrust_mn` 换算 N 和标准 gf，保留历史原始字段用于追溯，不混用 9.8 与 9.80665。
- 未人工采用的重复集合不能建模；多重采用阻止受影响组；不同配置和同电压多实验不能自动合并。
- 单点组仍完整读取、可查看，拒绝自动补成曲线。数据库入口即使只有一层电压也禁止外推。
- GUI 确认选择和运行前都会检查数据库快照是否变化；变化后要求重新选择。
- 新增追溯 JSON 导出，保存参数、电池/推进输入、数据库来源定位和原值、转换口径及结果汇总。未复制或修改活动 SQLite。
- 没有部署交接说明中的探索性拟合系数，没有推定 12.6 V / 13000 rpm 标定关系，也没有生成未测电压下的最大推力模型。
